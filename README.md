# Система управления зоопарком (Zoo Management System) — КР1

Консольная информационная система учёта посетителей и бронирований билетов в зоопарк.
Java 17, JDBC, PostgreSQL, Maven, Apache POI (экспорт в Excel).

## Запуск с нуля

### 1. Поднять PostgreSQL

Через Docker:
```bash
docker run --name pg-zoo -e POSTGRES_PASSWORD=********* -e POSTGRES_DB=zoo_db -p 5432:5432 -d postgres:18
```

Или через локально установленный PostgreSQL — создайте БД `zoo_db` вручную.

### 2. Создать таблицы и загрузить структуру

```bash
psql -h localhost -U postgres -d zoo_db -f src/main/resources/schema.sql
```
*(Пароль — `**********`, если использовали команду docker run выше).*

### 3. Проверить настройки подключения

Откройте `src/main/resources/database.properties` (или проверьте параметры внутри `DatabaseConfig.java`) и при необходимости поправьте логин/пароль/порт под вашу конфигурацию:

```properties
db.url=jdbc:postgresql://localhost:5432/zoo_db
db.user=postgres
db.password=postgres
```

### 4. Собрать и запустить

Откройте терминал в корневой папке проекта (где находится `pom.xml`) и выполните:

```bash
mvn clean compile
mvn exec:java -Dexec.mainClass="com.zoo.Main"
```

Либо через IDE (IntelliJ IDEA, Eclipse, VS Code): откройте файл `src/main/java/com/zoo/Main.java` и нажмите кнопку **Run** (зеленый треугольник) рядом с методом `main`.

## Что уже реализовано (по чек-листу ТЗ)

### 1. Главное меню (`ConsoleMenu`)
Реализовано циклическое интерактивное консольное меню, адаптированное под предметную область зоопарка. Программа возвращается в меню после каждого действия и не завершается аварийно:
1. Посетители (Управление/CRUD)
2. Бронирования (Управление/CRUD основной сущности)
3. Поиск бронирований и посетителей
4. Фильтрация и сортировка
5. Статистика системы
6. Экспорт данных в Excel
7. Вывести таблицы базы данных
0. Выход

### 2. Предметная модель и CRUD
- **Связанные сущности:** Посетитель (`Visitor` — клиент системы) и Бронирование (`Booking` — основная сущность) с жесткой связью «Один-ко-многим» по внешнему ключу `visitor_id`.
- **Полный CRUD для Booking:** Создание бронирования, вывод всех записей в консоль, получение информации по конкретному ID, изменение параметров брони и удаление.
- **Использование Enum:** Статусы жизненного цикла бронирования строго типизированы через перечисление `BookingStatus` (`PENDING`, `CONFIRMED`, `CANCELLED`).

### 3. Бизнес-правила и обработка ошибок
В слое `ZooServiceImpl` программно проверяются **5 обязательных бизнес-правил** с генерацией `BusinessException`:
1. Запрет создания бронирования на несуществующего или незарегистрированного посетителя (`visitor_id`).
2. Обязательное заполнение ключевых полей (непустое имя посетителя, корректный номер телефона).
3. Запрет на установку некорректного или непредусмотренного бизнес-логикой статуса брони.
4. Запрет на изменение данных или переходы из терминальных статусов (например, нельзя редактировать отмененное `CANCELLED` бронирование).
5. Запрет на сохранение некорректных количественных данных (например, отрицательное число билетов или некорректный возраст посетителя).

**Обработка некорректного ввода:**
- Перехвачен ввод текста вместо чисел (защита от `InputMismatchException` при вводе ID или пунктов меню).
- Реализована обработка отсутствия записей в БД по запрашиваемому ID (`EntityNotFoundException` / `BusinessException`).
- Реализован безопасный отлов инфраструктурных ошибок подключения к PostgreSQL и выполнения некорректных SQL-запросов (`DatabaseException`).

### 4. Поиск, фильтрация, статистика и экспорт
- **Поиск (2 способа):** Поиск посетителей по имени (или номеру телефона) и поиск бронирований по конкретной дате посещения зоопарка.
- **Фильтрация (2 фильтра):** Фильтрация списка бронирований по текущему статусу (`BookingStatus`) и по диапазону дат / количеству проданных билетов.
- **Сортировка (2 способа):** Сортировка записей по дате создания бронирования и по количеству забронированных мест (с использованием Java Stream API).
- **Статистика (5+ показателей):** Отдельный экран, агрегирующий данные: *Всего посетителей, Всего бронирований, Бронирований в статусе PENDING, Бронирований в статусе CONFIRMED, Общее количество забронированных билетов*.
- **Экспорт данных:** Выгрузка актуального среза таблиц из PostgreSQL в полноценный файл Excel (`bookings_report.xlsx`) с помощью библиотеки **Apache POI**.

### 5. Архитектура и требования к JDBC / БД
- **Разделение по слоям:** Логика декомпозирована по ТЗ: `Console UI (ConsoleMenu)` -> `Service (ZooServiceImpl)` -> `Repository / JDBC (BookingRepositoryImpl)` -> `PostgreSQL`. SQL-запросы полностью инкапсулированы внутри репозиториев.
- **Требования к JDBC:** Все запросы написаны исключительно через `PreparedStatement` с параметризацией (`?`). Конкатенация строк в SQL запрещена. Ресурсы (`Connection`, `Statement`, `ResultSet`) закрываются через `try-with-resources`.
- **Требования к БД:** В файле `schema.sql` объявлены ограничения целостности: `PRIMARY KEY`, `FOREIGN KEY` (связь `bookings.visitor_id -> visitors.id`), свойства `NOT NULL`, `UNIQUE` для контактов. Написаны скрипты для генерации начальных демонстрационных данных (минимум 5 посетителей и 10 бронирований).
